## 🚀 How It Works

### Video Resolution Priority
1. **Primary:** Explicit video_url property from sign data
2. **Secondary:** Lookup in SIGN_VIDEO_URLS mapping by sign ID
3. **Tertiary:** Lookup by gloss name (case-insensitive)
4. **Fallback:** Auto-generated candidates from gloss variations
5. **Last Resort:** `/videos/dataset-videos/` and `/dataset-videos/` paths

### Lesson Video Coverage
When a lesson loads:
1. Each sign in the lesson is resolved to its video
2. Video URLs are verified through the mapping system
3. Fallback candidates are generated automatically
4. The SignDisplay component handles playback with multiple retries

### Error Handling
- If a video fails to load, the next candidate URL is tried automatically
- If all candidates fail, an error state is shown (graceful degradation)
- System logs which video attempt succeeded for debugging

## 📝 Usage Examples

### In Components
```typescript
import { SignDisplay } from "@/components/common/SignDisplay";

// With sign ID for mapping lookup
<SignDisplay 
  gloss="FEVER"
  meaning="High body temperature"
  signId="fever"  // Will auto-lookup video in mapping
  videoUrl={currentSign.video_url}
  steps={currentSign.steps}
/>
```

### Video System Utilities
```typescript
import { 
  getSignVideoUrl,
  generateVideoUrlCandidates,
  validateLessonVideosCoverage 
} from "@/config/video-mapping";

// Get video URL for a sign
const videoUrl = getSignVideoUrl("fever");

// Generate candidates for fallback
const candidates = generateVideoUrlCandidates("FEVER", "fever");

// Verify lesson completeness
const coverage = validateLessonVideosCoverage("lesson-clinical-triage", 
  ["fever", "injury", "exam", "interview"]
);
```
